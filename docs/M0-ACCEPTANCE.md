# M0 Acceptance Criteria — 核心动画样片

## 目的
本里程碑不是完整游戏。它只回答一个问题：玩家点击一次鱼篓后，“夜师傅吃鱼 → 天屎降临 → 若无其事”的 3–5 秒核心喜剧动作是否成立。

## A. 页面与视觉
- [ ] 页面可直接从 index.html 启动，无构建步骤也能运行。
- [ ] 以 390×844 左右手机竖屏为主要验收尺寸。
- [ ] 背景为淡水彩池塘感，低对比、低存在感。
- [ ] 夜师傅始终是画面视觉主体，颜色/对比明显高于背景。
- [ ] 夜师傅站在叶子较少的树枝上。
- [ ] 画面正下方存在竹编鱼篓。
- [ ] 第一次进入显示“点击投喂”，点击后淡出。
- [ ] 不出现底部动作流程图、开发说明或调试 UI 于正常玩家界面。

## B. 投喂
- [ ] 点击鱼篓只生成一条鱼。
- [ ] 点击后立即锁定，流程结束前重复点击无效且不排队。
- [ ] 鱼从鱼篓方向被抛入水中，而非直接飞入鸟嘴。
- [ ] 每次随机选择左前/正前/右前三个落鱼点之一。
- [ ] 鱼落水有克制的小水花，随后短距离游动。
- [ ] 夜师傅头部/视线随落点变化。

## C. 捕食与吞咽
- [ ] 夜师傅从缩脖待机突然快速伸颈捕食。
- [ ] 三个落点对应三个可辨认的伸颈方向。
- [ ] 捕食速度明显快于鱼游动。
- [ ] 叼鱼后随机出现：直接吞；或鱼尾轻扑腾后吞。
- [ ] 仰头吞咽时颈部明显拉长并变粗。
- [ ] 不出现鱼在颈部内部的透视/显影。
- [ ] 吞咽后身体比投喂前略圆润。

## D. 天屎动作
- [ ] M0 每次投喂都强制触发天屎。
- [ ] 前摇为轻微下蹲。
- [ ] 仅腹部与尾部羽毛变蓬松。
- [ ] 头顶、颈部、背部羽毛仍平整服帖。
- [ ] 白线从靠尾部的正确位置出现。
- [ ] 只有一股细长连续白线，不是多股、圆球或 emoji。
- [ ] 白线快速向下延伸并落入水面。
- [ ] 落水有“啪嗒”感和水彩涟漪。

## E. 恢复
- [ ] 排泄后夜师傅身体回升。
- [ ] 腹尾羽毛恢复。
- [ ] 双翅只做小幅扑动，不完全展开。
- [ ] 最终恢复缩脖待机，形成“若无其事”的感觉。
- [ ] 恢复后鱼篓重新可点击，可再次完整播放。

## F. 技术
- [ ] requestAnimationFrame 驱动动画。
- [ ] 有明确状态机，而不是大量互相嵌套的 setTimeout。
- [ ] 状态逻辑与绘制逻辑分离。
- [ ] 正式美术资源可通过 asset/config 层替换，不需要重写状态机。
- [ ] 不依赖外部 CDN 或网络资源。
- [ ] Chrome/Edge 桌面模拟手机尺寸可运行。
- [ ] 浏览器控制台无未捕获异常。
- [ ] README 写清楚启动方式、M0 范围和已知限制。

## 非本里程碑
概率、8 条鱼完整循环、未触发随机动作、鸟运签、捞签、图鉴、分享、小红书 API、水门礼，全部留到 M1 以后。
